Overview

Scope: this guide documents one setup only — a fresh Ubuntu 24.04 EC2 instance converted in place to Windows 11 Pro with bin456789/reinstall. It is not a guide to any other project.

Licensing: the installer provides deployment only, not a Windows licence or activation. For personal testing use a time-limited Evaluation ISO. For production use an AWS Windows Server AMI (licence included) or a compliant Dedicated Host + Enterprise route. See Security.

Time: 20–45 minutes for the Windows install itself, plus setup and verification.

1 · Prerequisites

  • Instance: at least 2 vCPU / 8 GB RAM in practice (tested: m7i-flex.large, x86_64).
  • Root volume: at least 64 GB, 80 GB recommended. An 8 GB disk will fail.
  • AMI: Ubuntu Server 24.04 LTS (HVM), amd64. SSH user: ubuntu.
  • Key pair: a .pem you hold, with chmod 400.
  • Security group (your IP only, temporary): SSH 22, RDP 3389, HTTP 80.
ssh -i ~/.ssh/YOUR_KEY.pem ubuntu@YOUR_PUBLIC_IP

Success: Ubuntu 24.04 welcome text. Permission denied (publickey) means wrong key, wrong user, or wrong security group.

Backup first: EC2 Console → Instances → Actions → Images and templates → Create image. Note the AMI ID. Do not delete it until Windows is verified. Rollback is launching a new instance from that AMI — there is no in-place undo after the disk is erased.

4 · Main installation — Windows 11

The script auto-bypasses Windows 11 hardware limits (TPM/Secure Boot) and auto-installs AWS drivers (ENA network, NVMe storage, VMClock, PCI serial).

curl -O https://raw.githubusercontent.com/bin456789/reinstall/main/reinstall.sh
ls -lh reinstall.sh
bash scripts/install-windows11.sh

Or, directly (replace the placeholders — never use a real password in a document):

bash reinstall.sh windows \
  --image-name "Windows 11 Pro" \
  --lang en-us \
  --username YOUR_WINDOWS_USERNAME \
  --password 'YOUR_WINDOWS_PASSWORD' \
  --rdp-port 3389 \
  --allow-ping
Password rule: at least 8 characters, upper + lower + digit + special, and it must not contain the username. A password containing the username is liable to be rejected by Windows policy.
Business Editions ≠ installed edition: the ISO file is named “Business Editions”, but the installer is told finalos_image_name='windows 11 pro', so the installed edition is Pro. Verify it in step 12.

If automatic ISO lookup fails, use the README Evaluation method:

bash reinstall.sh windows \
  --image-name "Windows 11 Enterprise LTSC 2024 Evaluation" \
  --iso "https://go.microsoft.com/fwlink/?linkid=2289029"

Cancel before reboot only: bash reinstall.sh reset. The script prints an INFO block and returns to the prompt — it does not reboot by itself.

5 · Reboot and installation stages

reboot

SSH closing with “Connection reset by peer” is normal. Do not SSH back in.

  1. Console screenshot: Booting 'reinstall (windows)'
  2. Windows PE: AWSNVMe.inf loaded, DiskPart, MININT-PC (temporary PE name)
  3. Installing Windows 11 — percentage rising, several automatic restarts
  4. Windows login screen

Wait 20–45 minutes. Check only the console screenshot and the installer WEB log printed in step 4. Do not press Cancel and do not stop the instance.

6 · First RDP login

  • Computer: YOUR_PUBLIC_IP:3389
  • Username: .\YOUR_WINDOWS_USERNAME (then bare username if that fails)
  • Password: the password from step 4

If RDP fails, check the screenshot stage first — if the installer is still running, RDP cannot work yet. Then check the security group and IP.

7 · Inside Windows — first setup

  1. Change the Windows password immediately, especially if it was ever shared.
  2. Device Manager: confirm Amazon Elastic Network Adapter and AWS NVMe Controller, with no warnings.
  3. Run Windows Update until no important updates remain.
  4. Set time zone, region, and keyboard. Enable Windows Firewall.

8 · Networking, ports, and firewall

Remove HTTP 80. Restrict RDP 3389 to your IP (/32). Do not widen RDP to 0.0.0.0/0 as a shortcut. Full rules are in examples/security-group.md.

aws ec2 revoke-security-group-ingress \
  --group-id sg-xxxxxxxx \
  --protocol tcp --port 80 --cidr YOUR_IP/32

9 · Background services and automatic startup

Nothing extra is needed for a basic desktop: starting the instance starts Windows, and Windows starts its own RDP service. If you need a program on login, use Task Scheduler or the Startup folder, and document it so the next rebuild repeats it. Do not install an SSH server on Windows without a documented reason.

10 · Security hardening

  • Password rotated after first login; RDP restricted to your IP; Windows Update current.
  • No .pem, password, or key in any file, screenshot, or repository.
  • Before imaging a Windows AMI, remove temporary passwords, test files, and downloads.
  • Full rules: docs/SECURITY.md in the repository.

11 · Backup and restore

bash scripts/backup-ami.sh
bash scripts/restore-from-ami.sh

Restore always means launching a new instance from an AMI, not repairing the old disk. Keep the known-good AMI until the new instance passes verification. Compute billing stops when an instance is stopped; EBS, AMI, and snapshot storage keep billing.

12 · Verification checklist

Do not declare success until every row passes.

  • Instance Running, status checks passed
  • Console screenshot shows Windows login screen, not the installer
  • RDP login as .\YOUR_WINDOWS_USERNAME succeeds
  • Settings → System → About: Edition is Windows 11 Pro
  • Device Manager: Amazon Elastic Network Adapter, no warning
  • Device Manager: AWS NVMe Controller, no warning
  • Internet works from inside RDP
  • Windows Update: no important updates pending
  • Security group: HTTP 80 removed, RDP restricted to your IP
  • A verified Windows AMI exists, named and dated

13 · Troubleshooting

SSH Permission denied: wrong key, wrong user (ubuntu), or wrong security group. Key must be chmod 400.

RDP will not connect: check screenshot stage, security group, Running state, and public (not private) IP, in that order.

RDP login fails: try .\username, then bare username. Check the password does not contain the username.

Stuck at a percentage: wait at least 45 minutes total. A slowly moving percentage is not stuck.

Wrong edition / missing driver / will not boot: wrong edition needs a clean reinstall; a missing driver needs AWS drivers from AWS docs; a failed boot needs a restore from AMI. Full table: docs/TROUBLESHOOTING.md.

14 · Removal and clean reinstallation

bash scripts/uninstall.sh

Removal order: stop → optional final AMI → terminate → deregister AMI → delete snapshots → delete unattached volumes → rotate passwords/keys. Clean reinstallation starts again at step 1 with a fresh Ubuntu instance — do not reuse a half-installed Windows disk.

FAQ

Is Business Editions the same as Enterprise?
No. It is the ISO file name. The installed edition is the one named by --image-name. Verify it in Settings → About.

Is this free tier?
No, in practice. A large class instance and a 64–80 GB disk are not free-tier sized. Stop the instance when idle and check current pricing.

Can I use ARM / Graviton?
Only with an ARM64 Windows ISO. This guide's commands are the x86_64 path, which was the tested path.

Do I need API keys?
No third-party API keys exist for this setup. Authentication is: AWS key pair for SSH, and Windows username/password for RDP. AWS CLI backup scripts use your normal AWS CLI configuration, not a key in this repo.
